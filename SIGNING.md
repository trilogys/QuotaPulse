# AI Quota Native — Signing Guide

AI Quota contains **two independently signed bundles**:

1. `AIQuotaApp` — main application
2. `AIQuotaWidget` — Widget Extension (`.appex`)

Both provisioning profiles must belong to the same Apple Developer team and authorize the same App Group plus a compatible shared Keychain group.

For users with only one app provisioning profile, use `AIQuota-app-only-resign.ipa`. That build omits the Widget extension and does not require App Group or shared Keychain entitlements. A `.p12` file by itself is never sufficient; iOS signing also requires a compatible provisioning profile.

## Recommended: signed IPA in GitHub Actions

Create these repository Actions secrets:

- `AIQUOTA_P12_BASE64`
- `AIQUOTA_P12_PASSWORD`
- `AIQUOTA_APP_PROFILE_BASE64`
- `AIQUOTA_WIDGET_PROFILE_BASE64`

On macOS you can prepare the base64 values with:

```bash
base64 -i certificate.p12 | pbcopy
base64 -i App.mobileprovision | pbcopy
base64 -i Widget.mobileprovision | pbcopy
```

Then run:

```text
Actions → ipa → Run workflow
build_type = signed
```

Choose:

- `debugging` for Development profiles
- `release-testing` for Ad Hoc / registered-device distribution

The workflow derives Team ID, exact app/widget Bundle IDs, common App Group, compatible Keychain group and profile names directly from the two provisioning profiles. It does **not** require a separate Team ID secret or manual identifier input.

## Local Mac signed IPA

```bash
brew install xcodegen
export P12_PASSWORD='your-p12-password'

./Scripts/build_signed_ipa.sh \
  certificate.p12 \
  App.mobileprovision \
  Widget.mobileprovision \
  release-testing
```

The script creates a temporary macOS Keychain, imports the `.p12`, installs the two profiles temporarily, derives signing configuration, verifies profile compatibility, exports the IPA, verifies app + Widget signatures/entitlements, then removes the temporary Keychain.

## Inspect profiles

```bash
./Scripts/inspect_mobileprovision.sh App.mobileprovision
./Scripts/inspect_mobileprovision.sh Widget.mobileprovision
```

The profiles need:

- same Team ID / compatible AppIdentifierPrefix
- exact Bundle IDs (wildcard-only profiles cannot be safely auto-derived)
- a common `com.apple.security.application-groups` value
- compatible `keychain-access-groups`
- valid expiration date

You can explicitly validate them after deriving the config:

```bash
./Scripts/derive_signing_config.sh App.mobileprovision Widget.mobileprovision
./Scripts/verify_signing_profiles.sh App.mobileprovision Widget.mobileprovision
```

## Automatic signing with your Apple Developer account

```bash
./Scripts/configure_signing.sh \
  --team ABCDE12345 \
  --bundle com.yourname.aiquota \
  --style Automatic

./Scripts/bootstrap.sh
open AIQuota.xcodeproj
```

Enable the same App Group for both the app and Widget identifiers in Apple Developer/Xcode.

## Existing fixed profiles

If you already have fixed identifiers, configure their exact values rather than inventing new ones:

```bash
./Scripts/configure_signing.sh \
  --team ABCDE12345 \
  --bundle com.vendor.aiquota \
  --widget-bundle com.vendor.aiquota.widget \
  --app-group group.com.vendor.shared \
  --keychain-suffix com.vendor.shared \
  --style Manual \
  --app-profile "App Profile Name" \
  --widget-profile "Widget Profile Name"
```

## ESign / 轻松签 / other re-signing tools

Use the unsigned artifact generated by **Actions → ipa → unsigned**:

- Prefer `AIQuota-app-only-resign.ipa` when the tool or signing account provides only one profile.
- Use `AIQuota-resign.ipa` only when the tool can sign both `Payload/AIQuota.app` and `Payload/AIQuota.app/PlugIns/*.appex` and preserve or replace the critical entitlements consistently.

The full Widget build requires these entitlements:

- `com.apple.security.application-groups`
- `keychain-access-groups`

A generic single-profile re-sign may install the app while the Widget is missing or unable to read credentials.

## Security

Never commit `.p12`, private keys, provisioning profiles or certificate passwords. Common certificate/profile files plus local `SigningConfig.xcconfig` are git-ignored.
